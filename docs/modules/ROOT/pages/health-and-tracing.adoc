= Health and tracing

== Readiness check

With a SmallRye Health extension in the application (`quarkus-smallrye-health`), the extension publishes a readiness
check named `Topaz`. It is up when the authorizer answers `Info` and the directory answers `GetManifest`. A
directory without a manifest answers `NOT_FOUND`, which still counts as reachable. Any other error marks the check
down and reports the error in the check data.

Turn it off with `quarkus.topaz.health.enabled=false` (build time).

[source,shell]
----
curl -s localhost:8080/q/health/ready
----

== Tracing and metrics

The Topaz channels apply the global gRPC client interceptors, the ones annotated with
`@io.quarkus.grpc.GlobalInterceptor`. That is how `quarkus-opentelemetry` traces and `quarkus-micrometer` measures
gRPC client calls, so adding either extension instruments calls to both the authorizer and the directory. There is
nothing Topaz-specific to configure. Your own `@GlobalInterceptor` client interceptors apply to Topaz calls as well.
