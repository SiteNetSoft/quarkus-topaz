= Zanzibar connector
include::./includes/attributes.adoc[]

`quarkus-topaz-zanzibar` connects https://github.com/quarkiverse/quarkus-zanzibar[quarkus-zanzibar] to Topaz.
quarkus-zanzibar offers annotations such as `@FGARelation` and `@FGAPathObject` that guard REST endpoints with
relationship checks, and a `RelationshipManager` interface that stores and checks the relationships. This artifact
supplies the `RelationshipManager`, backed by the Topaz Directory, so the annotations are answered by Topaz. It is a
candidate for upstreaming as a quarkiverse connector.

[IMPORTANT]
====
Adding the artifact enables quarkus-zanzibar's filter, and `quarkus.zanzibar.filter.deny-unannotated-resource-methods`
defaults to `true`. Every REST endpoint without a quarkus-zanzibar annotation answers 403 until you annotate it, mark it
`@FGAIgnore`, or set the property to `false`.
====

== Installation

The artifact brings `quarkus-topaz` (the client and the Dev Service) and quarkus-zanzibar with it.

[source,xml,subs=attributes+]
----
<dependency>
    <groupId>org.sitenetsoft</groupId>
    <artifactId>quarkus-topaz-zanzibar</artifactId>
    <version>{project-version}</version>
</dependency>
----

== The relationship manager

The `RelationshipManager` bean calls the Topaz Directory through the `DirectoryClient`:

[cols="1,2,3"]
|===
|Method |Directory call |Behaviour

|`check` |Reader `Check` |Answers whether the relationship holds. A relation or permission that does not exist, an
unknown object type and a `NOT_FOUND` from the Directory all answer `false`. Any other error propagates.
|`add` |Writer `SetRelation`, once per element, in order |Idempotent: setting an existing relation succeeds. Errors
propagate.
|`remove` |Writer `DeleteRelation`, once per element |A relation that does not exist is ignored. Other errors
propagate.
|===

The subject relation is never set. Errors propagate as `io.grpc.StatusRuntimeException` and never turn into `true`.

== User identity

The principal name of the caller is the subject id. The subject type is the user type of the check: set it with
`@FGAUserType("user")` on the resource class or method. When quarkus-zanzibar hands over a blank user type, the
connector uses `quarkus.topaz.zanzibar.default-user-type` (`user` by default).

Topaz needs a directory object of that type and id, so the caller must exist in the directory; otherwise checks answer
`false`.

[WARNING]
====
quarkus-zanzibar's `quarkus.zanzibar.extract-user-type-from-roles` defaults to `true`. For a user with a single role it
turns the role name into the subject type. For Topaz the subject type is a directory object type (such as `user`), not a
role, so the check would use a type the manifest does not know. Either put `@FGAUserType("user")` on the resource, or set
`quarkus.zanzibar.extract-user-type-from-roles=false`, which makes `quarkus.topaz.zanzibar.default-user-type` fill the
type.
====

== Relations and permissions

`@FGARelation` can name a permission such as `can_delete` as well as a relation, because Topaz `Check` evaluates both.

== Walkthrough

The todo application of this repository's `integration-tests` module uses the manifest in
`integration-tests/src/main/resources/topaz/manifest.yaml`:

[source,yaml]
----
types:
  user: {}
  todo:
    relations:
      owner: user
    permissions:
      can_delete: owner
----

`FgaTodoResource` guards its endpoints with the annotations. The class sets the subject type, and the owner may read:

[source,java]
----
@Path("/fga/todos")
@ApplicationScoped
@FGAUserType("user")
public class FgaTodoResource {

    @GET
    @Path("/{id}")
    @FGAPathObject(param = "id", type = "todo")
    @FGARelation("owner")
    public Map<String, String> get(@PathParam("id") String id) { ... }
----

`@FGAPathObject` takes the object id from the path parameter `id`; the object type is `todo`. The check is
`todo:<id>#owner@user:<principal>`. Deleting names the permission:

[source,java]
----
@DELETE
@Path("/{id}")
@FGAPathObject(param = "id", type = "todo")
@FGARelation("can_delete")
public Response delete(@PathParam("id") String id) { ... }
----

Sharing is a write through the `RelationshipManager`. `FGARelation.ANY` lets any related caller through the filter; the
method then sets or removes the relation:

[source,java]
----
@PUT
@Path("/{id}/owners/{user}")
@FGAPathObject(param = "id", type = "todo")
@FGARelation(FGARelation.ANY)
public Uni<Response> share(@PathParam("id") String id, @PathParam("user") String user) {
    return manager.add(List.of(Relationship.of("todo", id, "owner", "user", user)))
            .map(v -> Response.noContent().build());
}
----

`unshare` is the same with `manager.remove`. The application's other endpoints are secured by the `topaz` route policy,
so its `application.properties` sets `quarkus.zanzibar.filter.deny-unannotated-resource-methods=false`.

== Errors

* An anonymous caller, and a caller that is unknown to the Directory, get 403. quarkus-zanzibar denies; it does not
challenge with 401.
* When Topaz is unreachable, the filter answers 500 after `quarkus.zanzibar.filter.timeout` (5s by default). That
timeout bounds the wait. `quarkus.topaz.deadline` applies to calls that reach Topaz; it was observed not to end a call
on a stalled connection.

== Configuration

The connector has one property. All other settings, `quarkus.zanzibar.*`, belong to quarkus-zanzibar; see its
documentation.

[cols="2,3"]
|===
|Property |Meaning

|`quarkus.topaz.zanzibar.default-user-type` |The subject type used when quarkus-zanzibar hands over a blank user type.
Default `user`.
|===

The full reference is in xref:configuration.adoc[Configuration reference].
